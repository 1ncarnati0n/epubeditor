# epubeditor

영어 EPUB을 블록(문단) 단위로 분해해 **Codex가 MCP로 한국어 번역**을 채워 넣고, 2단 대역 UI에서 검수·수정한 뒤, 한국어 폰트를 임베드해 번역된 EPUB으로 내보내는 로컬 에디터.

```
브라우저 (Svelte 5 UI) ──HTTP/SSE──┐
                                   ├── SvelteKit 서버 (127.0.0.1:5173)
Codex CLI ──MCP(Streamable HTTP)────┘     메모리 상태 + data/ 영속화
```

## 설치·실행

```sh
npm install
npm run fonts        # Pretendard·Noto Serif KR 다운로드 (최초 1회, OFL 라이선스)
npm run dev          # http://localhost:5173
```

프로덕션: `npm run build && npm start` (같은 포트 — `BODY_SIZE_LIMIT`/`ORIGIN` 포함).

## 사용 흐름

1. 브라우저에서 EPUB을 끌어다 놓기 → 챕터·블록으로 분해됨 (진행 상태는 `data/`에 저장, 같은 파일 재업로드 시 이어하기)
2. 상단 `Codex MCP` → `MCP 연결` 클릭 (최초 1회)
3. `번역 지침`에 문체·용어 규칙을 적고, `Codex MCP → 실행 설정`에서 모델·추론 강도·배치 크기 지정 (선택, 책마다 저장됨)
4. 현재 chapter 또는 책 전체 선택 → 번역 시작. Codex가 배치 단위로 번역하면 UI에 실시간으로 흘러들어옴 (치자색 = 초벌)
   - 한 문단만 손보고 싶으면 그 행의 거터 `▸` 버튼 — 블록 하나만 번역/재번역. 연속으로 눌러도 큐에 쌓여 차례로 처리됨
5. 오른쪽 칸에서 직접 수정(자동 검수됨) 또는 거터의 점을 눌러 검수 완료 (쪽빛 = 검수됨) — 검수된 블록은 chapter/책 번역이 덮어쓰지 못함 (블록 버튼은 명시적 의사이므로 덮어씀)
6. `조판`에서 출력 형식(번역만 / 원문 병기)·폰트·크기·행간·여백 조정 → `미리보기`로 확인
7. `내보내기` → 번역 주입 + 선택 폰트 서브셋(woff2) 임베드된 EPUB 다운로드 (epubcheck 통과)

## 검수 흐름

초벌을 검수하는 일은 수천 번 반복되므로 손이 키보드를 떠나지 않게 만들었다.

| 키 | 동작 |
|---|---|
| `↑ ↓` · `J K` | 블록 이동 (필터가 걸리면 보이는 행 사이에서만) |
| `Enter` | 번역 칸 편집 시작 · `Esc` 끝내기(저장됨) |
| `⌘ Enter` | **검수 완료 + 다음 초벌로** — 챕터가 끝나면 초벌이 남은 다음 챕터를 자동으로 연다 |
| `T` | 이 블록만 Codex로 다시 번역 |
| `⌘ F` | 책 전체에서 찾기 · `⌘ S` 지금 저장 · `?` 단축키 |

글을 치는 중에는 한 글자 단축키가 동작하지 않는다. 컬럼 머리글이 곧 필터다 — `전체 / 미번역 / 초벌 / 원문 바뀜`에 각 개수가 붙어 있고, `초벌`을 고르면 검수할 것만 남는다.

## 검색·치환

`⌘F`로 책 전체에서 찾는다(번역·원문 선택). **치환은 번역문에만** 적용되고 — 원문 보호 원칙과 같다 — `<em>`이나 `<a href>` 안쪽이 치환어와 겹쳐도 **텍스트 노드만 바꾸므로 마크업이 깨지지 않는다.** 바꾸기 전에 몇 개가 바뀔지 먼저 세어 보고, 실행하면 스냅샷이 자동으로 남는다.

## 책 정보 (제목·저자)

`정보` 패널에서 고친다. 원본 제목에 판매처 꼬리표가 붙어 나오는 책이 흔한데(`Grokking Data Structures (for ​ ​)` 처럼 zero-width 문자까지 박혀 있다), 그게 화면·파일명·내보낸 EPUB에 그대로 나가던 것을 여기서 정리한다.

한 번 고치면 네 곳이 같이 따라온다: 화면 위쪽 제목 · 책장 목록 · 내려받는 파일 이름 · 내보낸 EPUB의 `dc:title`/`dc:creator`.

- 저자를 비우면 빈 `<dc:creator/>`를 남기지 않고 **항목째 지운다** (epubcheck가 빈 값을 건다)
- 저자를 바꾸면 calibre가 남긴 정렬키 `opf:file-as`도 지운다 — 안 지우면 리더가 옛 저자명으로 정렬한다
- **원본 `source.epub`은 건드리지 않는다.** 고친 값은 작업 파일에 저장되고, 내보낼 때만 OPF에 쓰인다
- `dc:language`는 내보낼 때 늘 `ko`다 (EN→KO 전용 도구라 고를 이유가 없다)

## 번역 지침

`번역 지침` 패널에 문체·호칭·고유명사 표기 규칙을 적어두면 **어느 경로로 번역하든 같은 규칙이 적용된다.**

- **Codex** — 번역 요청 프롬프트에 함께 전달
- **다른 MCP 클라이언트** (Claude Code 등) — `get_blocks` 응답의 `translationGuide` 필드로 전달. 번역 직전에 매번 호출되는 자리라 지침을 고치면 **이미 연결된 세션에도 즉시** 반영된다 (서버 `instructions`와 툴 설명은 클라이언트가 캐시하므로 새 세션에만 반영)

책마다 따로 저장되고 작업파일에 함께 담긴다. **새 책은 기본 지침을 이미 들고 시작하므로** 책마다 넣고 저장할 필요가 없다 — 고칠 것만 고치면 된다. 지우고 되돌리고 싶으면 `예문 넣기`.

## 출력 형식

| 형식 | 결과 | 파일명 |
|---|---|---|
| 번역만 | 원문을 번역문으로 대체 | `{제목}-ko.epub` |
| 원문 병기 | 번역문 아래에 원문을 작게 병기 | `{제목}-대역.epub` |

병기는 형제 요소가 아니라 같은 블록 안의 `<span class="epubeditor-src">`다 — `li`·`td` 같은 블록에서도 목록 번호나 표 열이 깨지지 않는다. 미리보기와 내보내기가 같은 주입 함수(`epub/blocks.ts`의 `injectTranslations`)를 쓰므로 화면에서 본 것이 그대로 나간다.

원문의 **크기(0.5~1.0배)와 흐림(0.2~1.0)** 은 조판 패널에서 조절한다. 병기를 켰을 때만 슬라이더가 보인다 — 작게 할수록 흐리면 안 보이니 둘을 같이 움직이게 뒀다.

병기 원문 규칙은 전부 `!important`다. 원문 상자가 책 본문 **안에** 들어가는 `<span>`이라, 책이 `#id span{margin:0;font-size:100%;font:inherit}` 같은 리셋을 싣고 있으면(O'Reilly 책들이 그렇다) 클래스 하나로는 명시도에서 진다 — 크기·행간·간격이 통째로 죽고 흐림만 남는다.

## Codex 실행 설정

| 항목 | 설명 |
|---|---|
| 모델 | `~/.codex/models_cache.json`을 읽어 목록을 만든다 — 하드코딩하지 않으므로 `codex update` 후 새 모델이 그대로 뜬다. 비워두면 Codex CLI 기본값 |
| 추론 강도 | 고른 모델이 지원하는 값만 표시 (`model_reasoning_effort`) |
| 배치 크기 | 한 번의 `codex exec`가 처리할 블록 수 (1~50) |

앱은 `codex exec --ignore-user-config`로 실행한다(사용자 config의 notify 훅·trust 설정이 딸려오지 않도록). 위 설정만 `-m` / `-c`로 명시 전달된다.

### 번역할 chapter 고르기

좌측 `차례`의 체크박스로 **책 전체 번역이 돌 chapter를 고른다.** 표지·판권·색인처럼 번역이 필요 없는 것을 빼거나, 실패해서 건너뛴 chapter만 다시 돌릴 때 쓴다. 버튼은 언제나 "체크한 것만"을 뜻하고, 책을 열면 전부 체크된 상태라 아무것도 건드리지 않으면 결과가 예전과 같다.

저장하는 건 고른 것이 아니라 **뺀 것**(`session.excluded`)이다 — 기본 `[]`가 곧 "전부 대상"이라 예전 작업파일이 마이그레이션 없이 맞고, 책을 다시 올려 chapter가 늘어도 새 것은 자동으로 대상이 된다.

체크는 이 버튼에만 적용된다. `현재 chapter 번역`과 블록 버튼은 체크와 무관하다.

## 여러 권 오가기

`data/<bookId>/`에 책마다 따로 쌓이고, **헤더 제목을 누르면 책장**이 내려온다 — 제목·저자·진행 막대·검수 남은 수·마지막 작업 시각·용량. 다른 책으로 넘어갔다 돌아오면 **덮던 자리(챕터·커서·필터)에서 이어진다**(`session`으로 book마다 저장). 책이 없을 때의 첫 화면도 같은 책장이다.

- 전환 전에 지금 책을 먼저 디스크에 확정하므로 debounce 대기분이 새지 않는다
- Codex 번역 중에는 전환·삭제가 막힌다
- 지우기는 폴더째 삭제라 그 책의 번역도 함께 사라진다 — 열려 있는 책은 지울 수 없다

## 번역 속도

실측(20블록 배치 ≈ 55~70초) 결과 시간의 대부분은 **모델이 문단을 생성하는 시간**이다. `codex` 바이너리 시동은 0.05초로 무시할 수준이고, 배치를 키워도 총 출력 토큰은 같아서 이득이 작다. 실제 레버는 둘이다.

- **동시 실행** (기본 3, 1~4) — 가장 크게 갈리는 값. 일감을 **블록 ID 목록으로 미리 쪼개** 워커에 나눠주므로 겹칠 수 없고, 한 chapter 안에서도 병렬이 된다
- **빠른 처리**(`service_tier=fast`, 기본 켬) — 카탈로그 기준 1.5배. 할당량을 더 쓴다
- `실행 설정 → 속도 우선으로 맞추기` — 빠른 모델 + `low`. 번역은 추론이 많이 필요한 일이 아니다
- JobBar에 **블록/분·예상 완료 시각**이 뜬다. 설정을 바꿨을 때 이득을 숫자로 확인할 것

한도(429)에 걸리면 아래의 재시도가 백오프로 받아낸다.

## 번역이 실패할 때

OpenAI 쪽 일시 장애(`503 Service Unavailable` · `circuit_open`)는 드물지 않다. Codex CLI가 자체적으로 5번 재연결하다 포기하면 프로세스가 비정상 종료하는데, 그걸 잡 실패로 보면 254배치짜리 책 번역이 한 번의 딸꾹질로 통째로 죽는다. 그래서 두 겹으로 막는다.

- **batch 재시도** — 일시 장애로 판단되면 최대 5회, 2·4·8·16·32초 백오프. 대기 중에도 `중지`가 바로 먹는다. 배치마다 제출 즉시 저장되므로 재시도는 **남은 것만** 이어서 한다
- **영구 오류는 즉시 포기** — 로그인 필요·모델 없음 같은 건 다시 해도 같다
- **chapter 건너뛰기** — 재시도를 다 쓰면 그 chapter를 접어두고 다음으로 간다. 끝나면 Codex 패널에 실패 목록과 `실패한 chapter만 다시 번역`이 뜬다
- 오류는 stderr 원문 대신 한 줄 요약으로 보여준다 (원문은 서버 콘솔에)

## 번역 중인지 알아보기

- **창 맨 위 진행 띠** — 어느 뷰·어느 패널에 있든 보인다. 진행률·`n/total`·현재 챕터·예상 남은 시간·`중지`
- **차례에서 지금 번역 중인 챕터**가 치자색으로 표시된다
- **미리보기가 스스로 갱신된다** — 번역이 도착하면 1.5초 모아서 다시 그리고, 보던 스크롤 위치를 유지한다
- 방금 도착한 블록은 4초간 배경 + 치자색 가장자리 (현재 커서의 쪽빛과 구분)

## 미리보기가 원본에 가깝게 뜨도록

미리보기는 epub.js 같은 리더 엔진이 아니라 **원본 XHTML에 번역을 얹어 그대로 내보내는 것**이다. 그래서 리더 엔진이 공짜로 해주던 몇 가지를 직접 챙긴다.

**수식은 번역을 통과해도 살아남는다.** 수학책은 문단 한복판에 수식을 인라인 이미지나 MathML로 박는다 (실측: 한 권에 `<img>` 14,295개, 다른 한 권에 `<math>` 6,278개). 제출된 번역은 `sanitize.ts`를 지나는데, 예전 허용목록엔 `img`도 `math`도 없어서 **번역하는 순간 수식이 증발했다.** 지금은

- `img`를 허용하고 `src`·`style`도 남긴다 (`style`이 없으면 인라인 수식이 글줄에서 붕 뜬다)
- `math`·`svg`는 **서브트리째** 통과시킨다 — MathML은 태그가 서른 개가 넘어 하나씩 허용하는 건 지는 싸움이다
- MCP 툴 설명과 Codex 프롬프트가 이 셋을 그대로 복사하라고 명시한다

**본문 링크가 살아 있다.** `<a href="chapter4.xhtml#fn4_1">`을 그냥 두면 iframe 기준으로 `/preview/chapter4.xhtml` → 404다 (권당 548~1,842개). spine 문서를 가리키면 `/preview/<chapterId>#앵커`로 옮긴다. 같은 문서를 파일명으로 가리키는 각주도 흔해서(한 책은 548개 중 324개) 그 경우엔 앵커만 남긴다 — 안 그러면 문서를 통째로 다시 불러오며 보던 자리를 잃는다.

**수식은 강제 폰트에서 뺀다.** `body *{font-family:… !important}`가 `<mi>`·`<mo>`에 직접 매칭돼 수식이 한글 명조로 그려졌다. CSS엔 "조상이 math가 아닌 것" 선택자가 없으므로 되받아치는데, **명시도가 관건**이다 — 기존 규칙이 (0,0,6)이라 `body math *`(0,0,2)를 뒤에 둬도 아무 일도 안 일어난다. 같은 `:not()` 사슬을 붙여 (0,0,7)로 올려야 이긴다. 폰트는 `revert`(UA 수학 폰트로), 색은 `inherit`(본문 색을 따라가게 — 색 도구의 목적이 가독성이라).

**넓은 표·코드는 미리보기에서만 가둔다.** 미리보기 창은 화면 절반이라 코드블록이 페이지를 밀어낸다. `pre{overflow-x:auto}` · `table{display:block;overflow-x:auto}` · `img,svg{max-width:100%}`를 **미리보기 CSS에만** 넣는다. 내보낸 EPUB은 리더가 자기 화면에 맞추므로 책이 정한 대로 둔다.

**표시용과 저장용은 다르다.** 편집 화면 왼쪽 칸도 앱 오리진에 렌더되므로 `../Images/x.png`가 404다. 그래서 표시용 경로(`forEditor`)에서만 `src`를 `/res/…`로 옮기고, **저장된 번역과 내보낸 EPUB은 원래 상대경로 그대로** 둔다 — 섞이면 내보낸 책의 이미지가 전부 깨진다.

## 원문 보호

**원문은 저장하지 않는다.** `data/<bookId>/source.epub` 한 파일이 유일한 원본이고, 블록은 열 때마다 거기서 다시 파싱한다(13MB 책 기준 26ms). 지킬 사본이 없으니 손상될 사본도 없다.

- `project.json`은 **번역만** 담는다 — 원문 텍스트 0바이트. 실측 1,489KB → 350KB
- 번역마다 **그때 원문의 지문(`srcHash`)** 을 새긴다. 열 때 현재 원문과 대조해 다르면 그 블록을 `stale`로 표시하고, 하나라도 있으면 **내보내기를 차단**한다(배너에서 `그대로 확정` 또는 `번역 버리기`로 해소)
- `source.epub`이 통째로 바뀌면 `epubSha256` 불일치로 **프로젝트를 열지 않는다**
- 편집기로 나가는 원문은 표시용으로만 새니타이즈한다 — 악성 EPUB의 `<img onerror>`가 앱에서 실행되지 않는다. 내보내기·MCP는 원문 그대로(충실도)
- 왼쪽 칸은 읽기 전용. `원본 EPUB 내려받기`로 처음 올린 파일을 언제든 되찾을 수 있다

옛 형식(v1)은 처음 열 때 자동 변환되며, **그때 저장돼 있던 원문으로 지문을 계산**하므로 변환이 곧 기존 작업 전체에 대한 무결성 감사가 된다.

## 저장·되돌리기

편집·번역은 500ms debounce로 `data/<bookId>/project.json`에 원자적으로(tmp→rename) 자동 저장된다. 서버를 정상 종료(`Ctrl-C`/SIGTERM)하면 대기 중이던 저장까지 디스크에 남는다 — `SIGKILL`만은 마지막 500ms를 잃을 수 있다. 헤더의 `저장됨` 표시를 누르면 패널이 열린다.

- **지금 저장** (`⌘S`) — debounce를 기다리지 않고 즉시
- **작업파일** — 번역만 담긴 JSON 내보내기/불러오기(원문은 들어 있지 않다). 불러오기는 같은 `bookId`일 때만 받고, 스키마에 원문 필드가 없어 구조적으로 원문을 되돌려 넣을 수 없다
- **스냅샷** — 되돌릴 지점. chapter/책 번역 시작 직전, 작업파일 불러오기 직전, 되돌리기 직전에 자동으로 남고 최대 20개 보관

## MCP 연결

- **Codex**: UI의 `MCP 연결`이 `codex mcp add epub-editor --url http://localhost:5173/mcp`를 실행. Codex CLI 로그인 필요
- **Claude Code (이 레포)**: 기존 `.mcp.json`으로 자동 인식
- **Claude Code (다른 위치)**: `claude mcp add --transport http --scope user epub-editor http://localhost:5173/mcp`
- **Claude Desktop**: 커스텀 커넥터는 localhost 불가 → `claude_desktop_config.json`에 stdio 브리지 등록:
  ```json
  { "mcpServers": { "epub-editor": { "command": "npx", "args": ["mcp-remote", "http://localhost:5173/mcp"] } } }
  ```

툴 3종: `list_chapters`(진행률 겸용) · `get_blocks`(미번역 필터·페이지네이션, `blockIds`로 특정 블록 지정, 응답에 `translationGuide` 동봉) · `submit_translations`(배치 ≤50, 인라인 태그 보존 규약은 툴 설명에 내장).

## 구조 메모

- 블록 = spine 문서에서 `p, h1–h6, li, blockquote, …` 중 리프 요소. ID `s{spine}:b{block}`는 원본 불변 + 결정적 추출이라 안정
- 상태: `untranslated → machine(LLM 초벌) → reviewed(사람 검수)` — 내보내기는 초벌+검수 모두 반영
- 번역 HTML은 서버에서 인라인 태그 allowlist로 새니타이즈 (미허용 태그는 unwrap, script/style 삭제)
- EPUB 3.3의 `font/woff2` 코어 미디어 타입으로 폰트 임베드 — 구형 EPUB2 전용 리더에서는 폰트가 무시될 수 있음
- **책의 다크 모드 CSS**: 많은 책이 `@media (prefers-color-scheme: dark)`로 본문을 옅은 회색(#d6d7db 등)으로 바꾼다. 어두운 배경을 전제한 색인데 미리보기 종이는 늘 밝아서 OS가 다크면 글씨가 사라진다. `color-scheme`으로는 막을 수 없어서(문서·iframe 양쪽에 걸어봐도 `prefers-color-scheme`은 그대로다) **같은 미디어 쿼리로 되받아친다 — 미리보기 전용**. 내보낸 EPUB은 리더가 배경까지 바꾸므로 책의 다크 규칙이 맞다. 조판의 `본문 색`으로 직접 지정할 수도 있다(링크 제외)
- 폰트는 `body`가 아니라 `body *:not(code):not(pre)…`에 건다. 책이 `#content div{font-family:Verdana}` 같은 규칙을 갖고 있으면 **직접 매칭되는 그 규칙이 body에서 상속된 값을 이기기 때문**(조상의 `!important`는 조상에게만 중요하다). 등폭 요소는 책의 의도를 존중해 제외
